Note 1

Why a strip and not a log line

Controllers refused to give up paper flight strips even where a screen could have replaced them, because the physical record was doing safety work the screen did not.
After W. Mackay, "Is paper safer? The role of paper flight strips in air traffic control", ACM TOCHI 6(4), 1999. DOI 10.1145/331490.331491

An agent that remembers is only useful if you can argue with what it remembers. Three failures kill that, and every one of them is silent.

1. The answer that stopped being true

A vector store returns the closest sentence. It has no opinion about whether that sentence survived the migration three months ago. Throughline gives every kind of memory its own half-life, computes freshness by exponential decay against it, and returns anything past one half-life flagged rather than dropped. A contradicting write does not overwrite. It supersedes, stamps an end date, and leaves the old row queryable, because the reason a step changed is usually the thing you needed.

KindHalf-lifeWhy
entity_fact14 dHostnames, ceilings, owners. These rot fastest.
observation30 dWhat someone saw during an incident.
runbook_fact90 dProcedure. Changes on deploys, not on Tuesdays.
resolution180 dWhat actually fixed it. Worth keeping.
rejected_hypothesis365 dWhat did not work. Outlives everything, because it saves the most time.

2. The search that never ran

Recall returns a coverage verdict, and the verdict is computed from what actually happened, not from the result count. COVERED means the workspace was read. PARTIAL means the candidate cap of 200 was reached, so the answer is bounded and says so. UNKNOWN means the search could not run at all, and the agent is structurally prevented from converting it to "no prior incidents": the boundary rejects a claim of absence when coverage is UNKNOWN.

The approximate index is an accelerator, never a dependency. If it is unavailable, recall falls back to an exact cosine scan and prints that it did. It never presents degraded recall as full recall.

The embedder is a different case, and the schematic above draws it as a dashed line for a reason. Both paths compare against a query vector, so if the embedder fails there is no fallback to reach for: neither path runs, nothing is read, and the verdict is UNKNOWN. That is the honest answer, and it is the one the product exists to be able to give.

3. The eviction that ate the newest entry

Eviction that scores by usage will always eat the entry with no usage history, and that is the one written an hour ago. So the grace window is checked before the score is consulted, and the protection deadline is stamped on the row at write time from the policy that wrote it. A policy applied later at read time cannot un-protect what an earlier policy protected. Every sweep publishes what it removed and what it refused, and removal writes a tombstone rather than a hole.

The number is never written by a model

Scoring is a deterministic function of similarity, freshness, confirmation count and contradiction count, with fixed weights. The language model writes the sentence around the number. It never writes the number, and it never decides the verdict.

What the database is doing

CockroachDB is the system of record. The vector index is declared on (workspace_id, is_live, embedding), and the prefix matters: a filtered nearest-neighbour query is only accelerated on the index's prefix columns, and recall always filters by workspace and liveness. is_live is a stored computed column derived from evicted_at, so the two cannot drift apart. Both of those were measured against the live cluster rather than taken from the documentation.
